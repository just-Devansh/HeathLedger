HEATH LEDGER — PROJECT ROADMAP
================================
Last updated: May 2026

----------------------------------------
PRODUCT VISION
----------------------------------------

A fast, minimal, mobile-first PWA expense tracker for a single user.
Replaces a raw text workflow ("1 Apr - 236 (Biriyani) + 45 (Rapido)")
with a structured but equally fast UI.

PRIMARY GOAL: Log an expense in under 5 seconds on mobile.

Core principles:
- Speed over features
- Personal, opinionated, not generic
- No backend, no auth, no complexity
- localStorage only — data stays on device
- Installable PWA — works offline

ARCHITECTURE DECISIONS (LOCKED IN)
----------------------------------------

- Category references: always by UUID (categoryId), never by name string.
  Legacy entries (category string only) are migrated on load.

- Quick action shortcuts: stored as [{name, categoryId}] in
  heath_ledger_quick_actions. name is the display label (e.g. "Rapido"),
  categoryId is the stable UUID. name=null means legacy migrated entry,
  falls back to category name at render time.

- No Redux / no Zustand. State lives in App.jsx and flows down as props.
  CategoryManager manages its own local state and persists on every mutation.

- html2canvas export: all layout uses position:absolute for right-aligned
  values (flexbox and table are unreliable). Every text element needs
  explicit line-height and padding-bottom to prevent clipping.

----------------------------------------
NON-GOALS (DO NOT BUILD)
----------------------------------------

- Authentication or multi-user support
- Bank integrations or credit/debit accounting
- AI insights or complex analytics
- Nested / hierarchical categories
- CSV export (JSON backup already exists)
- Backend or cloud sync
- Budget limits or alerts
- Recurring income tracking
